## P0-1：三报对"今天做什么"互相矛盾

### 证据

**早报**内嵌 `today_actions` 数组给出 **8 条动作**，其中 **3 条直指现有持仓**：

| 优先级 | 标的 | 动作 | 置信 | 理由原文 |
|---|---|---|---|---|
| prio 0.5（最高） | 西部超导 688122 | **减仓** | 0.8 | 投资逻辑已破（broken）：持仓应减仓/兑利退出，逻辑破坏优先于估值置信度不足 |
| prio 1 | 国电南瑞 600406 | **兑利 33%** | 0.6 | 论点仍成立 · regime C · 当前16.7% / 目标259.0% |
| prio 1 | 紫金矿业 601899 | **兑利 33%** | 0.6 | 论点仍成立 · regime C · 当前15.4% / 目标238.0% |

**午报**结论：「✅ 今天什么都不做」「今日可行动项：无 actionable 决策」
**晚报**结论：「⑤ 明日关注：🟢 明日无特别操作」

### 矛盾性质

早报说的西部超导减仓（最高优先级、置信 0.8、理由是"逻辑已破"），在午报和晚报里**既没有被执行，也没有被结转、没有被标记为"已人工忽略"、也没有出现在任何位置**——它就这么消失了。

你早上看完报告得到一条明确指令，中午和晚上再看，报告告诉你"没事"。这不是数据问题，是**动作没有状态跟踪**。

### 建议

动作应该是**有状态的对象**，跨报告继承：

```
早报生成动作 → 午报结转（已执行 / 未执行仍有效 / 已失效）→ 晚报结转（今日收盘前最后状态）
```

每个动作带：`动作ID | 标的 | 动作 | 触发价 | 当前状态 | 已挂起N个报告周期`

## P1-1：「仓位 100.9%」口径错误

### 源码

```python
# Ashare/noon_report.py:204
<div class="meta">总资产 ¥{total_assets:,.0f} · 现金 ¥{cash:,.0f} · 仓位 {total_assets/700000*100:.1f}%</div>

# Ashare/close_report.py:159
<div class="meta">总资产 ¥{total_assets:,.0f} · 现金 ¥{cash:,.0f} · 仓位 {total_assets/700000*100:.1f}% · {len(positions)} 只持仓</div>
```

### 问题

`total_assets/700000*100` = **总资产 ÷ 70万基准** = 706,347 / 700,000 = **100.9%**。

这是"总资产相对于初始资金的比例"，**不是"仓位"**。真实的持仓占比应该是：

```
持仓市值 108,447 / 总资产 706,347  =  15.4%
```

一个仓位 15% 的组合，报告显示 100.9%。如果你按报告理解成"满仓了"，那就完全错了。

### 建议

改为 `持仓市值/总资产*100`，或明确标注为「总资产/基准」。同时把「现金 84.6%」也补上，这样仓位+现金=100% 能自洽。

## P1-2：Q5 BLOCK 横幅基于陈旧 current_equity（误报）

### 证据

`Asset_OS/execution_gate.json` 中 context 实测值：

```
nav = 702065.0
cash_pct = 89.0
current_equity = 77270.0      ← 陈旧
equity_cap_amt = 70206.5
portfolio_over_cap = True     ← 由陈旧值推出的错误结论
```

`Asset_OS/execution_gate.py:90-116` 的 `build_context` 直接取 `portfolio.get("current_equity", 0)`，未做时效校验。

真实持仓权益是 **108,447**（按 today_snapshot 现价）或 **109,706**（按早报内嵌），而 cap 是 70,206.5 —— 无论用哪个真实值，`current_equity` 都**确实超过 cap**，所以 BLOCK 的**结论方向没错**，但**用的是三周前的旧数字**。

陈旧值疑似来源：`deliverables/Q5_acceptance_test.py:11` 硬编码 `{"equity_cap_amt": 70206.5, "current_equity": 77270}`。

### 影响

午报/晚报顶部的「组合 Regime 资本预算不足」红条会让你以为"系统不许我买"。数字来源不可信时，这个红条本身就是噪音。

### 建议

`current_equity` 必须从 `today_snapshot.json` 实时派生，并在报告中**标注数据来源与时间戳**。若确属超配，横幅应显示「当前权益 X / 上限 Y / 超出 Z」而不是只给一个 BLOCK。
