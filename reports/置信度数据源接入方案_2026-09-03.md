## 一、sector_breadth — 可纯本地算，零外部依赖

### 数据源

`QRS/data/market_data.db` 内 JOIN，无需任何外部请求：

```sql
SELECT i.industry,
       SUM(CASE WHEN s.change_pct > 0 THEN 1 ELSE 0 END) up,
       SUM(CASE WHEN s.change_pct < 0 THEN 1 ELSE 0 END) dn,
       COUNT(*) n
FROM stocks_spot s
LEFT JOIN stocks_info i ON i.code = s.code
WHERE s.change_pct IS NOT NULL
GROUP BY i.industry
```

### 实测结果（2026-09-03）

| 指标 | 值 |
|------|-----|
| 全市场有行情 | 5529 只 |
| 能归入行业 | **5451 只 → 覆盖度 0.986** |
| 上涨家数 | 1507 / 5451 = **27.6%** |
| 行业数（≥5只） | 31 个 |
| 上涨家数占优的行业 | **仅 1 个 → 行业广度 0.032** |

持仓 7 只所属行业：拉卡拉=非银金融、恒瑞=医药生物、国电南瑞=电力设备、紫金=有色金属、立讯=电子、西部超导=国防军工、云铝=有色金属。

行业广度前几名：国防军工 0.60（唯一 >0.5）、汽车 0.42、机械设备 0.36、轻工制造 0.34、建筑装饰 0.31、电力设备 0.32、医药生物 0.20、有色金属 0.17、电子 0.24。

> 这个信号本身很有价值：**市场普跌，31 个行业只有国防军工一个上涨面占优**。而我的持仓里 6 只在跌，唯一涨的立讯精密（+0.28%）在电子（广度 0.24）。

### 需拍板的口径问题（**直接影响能否过 ACTION 线**）

`sector_breadth` 这个 0~1 的值到底填什么，三种口径结果差很大：

| 口径 | 值 | 语义 | 最终置信度 | 等级 | 过 ACTION(0.75)? |
|------|-----|------|-----------|------|-----------------|
| **A 覆盖度** | 0.986 | 数据质量（与其他维度一致） | **0.770** | HIGH | ✅ 过 |
| **B 行业广度** | 0.032 | 市场状态（31行业仅1个占优） | 0.627 | MEDIUM | ❌ 不过 |
| **C 个股广度** | 0.276 | 市场状态（1507/5451 上涨） | 0.663 | MEDIUM | ❌ 不过 |

（上表 market 固定 0.69、fund_flow 用最严格的半衰期 24h 计算）

**我的倾向：口径 A + 把 B/C 作为元信息单独输出。**

理由：置信度衡量的是「我有多相信这个结论」，核心是**数据质量**；而市场广度是**市场状态**，属于决策上下文，不是数据质量。把市场状态混进置信度会导致「市场越差、置信度越低」——这在语义上是两件事，混淆后无法解释。

但这条我说了不算，需要你定。

## 二、fund_flow — 有源但滞后 3 天

### 数据源

`Ashare/data/tencent/westock_live.json` → `holdings[code].MainNetFlow`
- 主链自动生成，无需手动触发
- 覆盖 **6/7**（云铝股份缺值）
- asof = **2026-08-31**，距今约 77 小时

### 需拍板的时效半衰期

资金流是**日频**数据（每日收盘后更新），衰减速度应慢于分钟级行情，但快于季度财务。三个选项：

| 半衰期 | age=77h 的衰减 | fund_flow 值 | 最终置信度 | 等级 |
|--------|---------------|-------------|-----------|------|
| 24h（严格） | 0.108 | 0.093 | **0.770** | HIGH |
| 48h（平衡） | 0.329 | 0.282 | **0.808** | HIGH |
| 72h（宽松） | 0.477 | 0.409 | **0.833** | HIGH |

（上表 sector_breadth 用口径 A=0.986）

**三种都能过 ACTION 线**，区别只在「3 天前的资金流还算不算数」。

我的倾向：**48h**（资金流是日频，按交易日衰减，48h 大致对应"隔了一个交易日仍可参考，隔了三个交易日基本失效"）。

### 若要真正提升，得刷新数据

当前瓶颈是数据滞后。若能刷到当日（age≈12h，半衰期48h）：

- fund_flow = 0.857 × 0.841 = **0.721**
- 置信度 → **0.896**

若再叠加盘中跑（market 数据龄≈0 → 1.0）：置信度 → **0.969**

**结论：资金流数据刷到当日，比调任何参数都管用。**

## 三、调研中新发现的问题：data_completeness 被双重计入

`confidence_budget.py:75-90` 中，`data_completeness` **既作为加性维度、又作为乘性因子**：

```python
for dim, weight in norm_w.items():      # ← 循环里包含 data_completeness
    ...
    contrib = val * weight
    total += contrib                     # ← 加性：dc=1.0 时白送 0.15

dc = dims.get("data_completeness")
if dc is not None:
    total *= max(0.0, min(1.0, float(dc)))   # ← 乘性：设计意图是「完整性低则整体打折」
```

实测验证（口径A场景）：
- 双重计入 → **0.770**
- 只做乘性因子（不加性） → **0.620**

即 **dc=1.0 时等于免费多拿 0.15 分**，而 0.15 恰好是能否跨过 ACTION 线的量级。

这是**既有设计**，不是本次修复引入的，我也没动它。但它让「数据完整性」这个防幻觉机制在数据完整时反而变成加分项，与 docstring 里"防幻觉核心"的定位有张力。

**需拍板：修不修？** 修的话只影响语义（数据完整时不再白送分），不影响 dc<1 时的保守行为。
