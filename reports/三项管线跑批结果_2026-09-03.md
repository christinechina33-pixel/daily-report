## 二、新发现 A：认知层置信度失真（0.15 是假的）

**这个数字不能信**。跑出来 `confidence=0.15 / LOW / allowed_action=false`，拆解后发现问题不在"判断结果低"，而在**输入全零**：

| 维度 | value | weight | contribution |
|------|-------|--------|--------------|
| market | 0.00 | 0.15 | 0.000 |
| fund_flow | 0.00 | 0.20 | 0.000 |
| sector_breadth | 0.00 | 0.15 | 0.000 |
| fundamentals | 0.00 | 0.25 | 0.000 |
| price | 0.00 | 0.10 | 0.000 |
| **data_completeness** | **1.00** | 0.15 | **0.150** |

85% 权重的实质维度全部为 0，全部 0.15 分来自 `data_completeness` 一项。

### 根因（两处叠加，已实测证实）

**Bug A — schema 不匹配**  
`cognition/cognitive_layer_step.py:131-140` 的 `_load_health()` 把整个 `run_health.json` 当 `system_health` 传入。但真实健康度在 `dimensions` 子字典里，且 key 名完全不同（`qrs_research` / `quote_coverage` / `news_freshness` / `market_context` / `logic_state_coverage`）。  
`confidence_budget.py:129-133` 用 `.get(key, 0.0)` 兜底 → 5 个 key 顶层全不存在 → **静默归零，不报错**。

**Bug B — bool 被当成数值**  
`confidence_budget.py:143` 用 `isinstance(v, (int, float))` 判断数值，而 Python 中 `bool` 是 `int` 子类。顶层唯一被判为"数值型"的 value 是 `publish_ready=true` → 计为 1/1 → **data_completeness = 1.00 假满分**。

### 后果（最严重的一条）

`data_completeness` 的设计意图是"完整性低 → 总分打折"的**防幻觉核心机制**（`:87-90`）。这里完整性被误算成满分，打折机制**完全没触发**——本该压低的分数反而被 1.0 乘上去原样保留。

且该失真置信度直接传入 `synthesize_all(change_log, prices, conf, portfolio)`，意味着**刚才生成的 7 条五态合成全部基于 0.15 这个失真值**。

### 修复方案（待拍板，未执行）

1. `_load_health()` 增加 `dimensions` 子字典的 key 映射（`quote_coverage→market`、`market_context→sector_breadth` 等），或直接在 `run_health.json` 顶层补出 5 个标准 key
2. `_data_completeness()` 排除 bool：`isinstance(v, (int, float)) and not isinstance(v, bool)`
3. 增加 fail-loud：5 个实质维度全零时应报 `DATA_MISSING` 而非静默给 0.15
4. 修完后重跑认知层
